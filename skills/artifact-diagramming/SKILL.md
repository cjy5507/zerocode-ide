# 관계가 읽히는 그림

ZeroCode의 한 페이지에서 구조나 흐름을 설명할 때 사용한다. 만들기 전에 `Skill`로 `artifact-design`을
읽어 제목·테마·반응형·발행 규칙을 적용한다. 그림의 질문, 노드가 뜻하는 것, 연결이 뜻하는 것을 먼저 정한다.

| 관계 | 배치 | 표현 |
| --- | --- | --- |
| 순서·분기 | 한 방향 흐름 | 시작·끝, 화살표의 방향, 분기 조건 |
| 포함·소유 | 중첩 영역·트리 | 그룹 이름과 경계, 같은 깊이의 정렬 |
| 시스템 의존성 | 계층·군집 | 누가 누구에게 무엇을 요청하는지 연결에 이름 |
| 시간·책임 | 순서도·스윔레인 | 공통 시간 방향과 각 주체의 레인 |

연결이 교차하면 배치를 먼저 고친다. 의미가 다른 관계만 선 모양이나 화살표로 구분한다.
노드 이름은 짧게 하고 긴 설명은 그림 옆으로 옮긴다. 하나의 그림이 여러 질문을 떠안으면 부분 그림으로 나눈다.

## 인라인 SVG

- HTML에 `<svg viewBox="…" role="img" aria-labelledby="…">`를 직접 넣고 고유 id의 `<title>`과 `<desc>`를 연결한다.
  핵심 관계를 읽을 수 있는 문장이나 목록도 옆에 둔다. 외부 이미지로 SVG를 숨기면 테마 토큰을 상속하지 못한다.
- 노드·선·화살표·레이블은 `artifact-design`의 CSS 토큰과 `currentColor`를 쓴다. SVG 배경도 그 아티팩트가 정의한 페이지·패널 배경 토큰으로
  명시한다. 라이트와 다크에서 화살표 머리·경계·작은 글자가 사라지지 않는지 확인한다.
- `viewBox`에 여백과 화살표 머리를 포함하고, `preserveAspectRatio`로 비율을 유지한다. 텍스트 줄바꿈은
  `<tspan>`으로 제어한다. 폰트 폭 때문에 이름이 상자를 벗어나면 노드를 넓히거나 레이블을 줄인다.
- 작은 화면에서 읽을 수 없을 만큼 축소하지 않는다. 전체 구조 미리보기와 `overflow-x: auto`인 상세 그림을
  쓰거나 부분 그림으로 접는다. 페이지 전체의 가로 스크롤은 피한다.
- 인쇄·단일 파일 내보내기도 읽히도록 SVG의 의미를 JS 실행에만 맡기지 않는다. 상호작용이 있으면
  키보드로도 같은 노드를 선택하게 하고 선택된 관계를 글로 설명한다.

실제 브라우저에서 양 테마와 좁은 폭을 확인한다. 레이블 겹침·끊긴 연결·잘린 marker를 고치고,
완성 HTML을 `Artifact publish`로 발행해 도구가 돌려준 URL을 건넨다.
